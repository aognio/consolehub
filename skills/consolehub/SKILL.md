# ConsoleHub Architecture & Protocol Guide

This skill provides comprehensive architectural and protocol guidance for ConsoleHub—a remote command-line application console and telemetry ingestion platform.

---

## 1. Core Architecture & Philosophy

ConsoleHub is a remote console with history, designed specifically for monitoring long-running command-line applications, background workers, and automation scripts across multiple host machines.

---

## 2. Ingestion Protocol & Client-Side ULID Process Registration

Client ingestion uses **JSON-RPC 2.0 over WebSockets** (`GET /api/v1/rpc/ws`).

### Process Registration Metadata Requirements:
* **Mandatory Client-Side ULID**:
  * `process.client_run_id`: A 26-character canonical Crockford Base32 ULID generated by the client application (e.g. `"01ARZ3NDEKTSV4RRFFQ69G5FAV"`). Mandatorily sent in `process.register` and `stream.resume`.
* **Mandatory Fields**:
  * `host.hostname`: Unique string identifying the machine (auto-detected via OS hostname if omitted).
  * `process.pid`: Integer process ID of the running instance (auto-detected via OS PID if omitted).
* **Optional Fields**:
  * `process.version`: Semantic application version string (e.g. `"1.4.2"`).
  * `host.platform`: Operating System name string (e.g. `"linux"`, `"darwin"`, `"windows"`).

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "process.register",
  "params": {
    "tenant": "engineering",
    "app": "telegram-replicator",
    "host": {
      "hostname": "vps-01",
      "platform": "linux"
    },
    "process": {
      "client_run_id": "01ARZ3NDEKTSV4RRFFQ69G5FAV",
      "pid": 42817,
      "version": "1.4.2",
      "command_line": "./app",
      "working_directory": "/srv/app"
    }
  }
}
```

## 3. Structured API Key Authentication

ConsoleHub generates self-verifying, high-entropy API keys:

* **Format**: `sk_<base62_payload>_crc32_<base62_checksum>` (e.g. `sk_3q2Z7x9P2R8LmNkJd4Hf6Y_crc32_2AB9XQ`).
* **Argon2id Hashing**: Raw API keys are displayed **once** upon creation with a warning and stored strictly as Argon2id hashes (`$argon2id$v=19$m=65536,t=1,p=4$...`).
* **Fast Validation**: Verification decodes Base62 entropy and validates the CRC32 checksum before checking the Argon2id hash.

---

## 4. Buffering, Batching & Circuit Breaker

* **Bounded Queue**: Clients buffer messages in a bounded queue (e.g. 10,000 items). On overflow, lowest priority/oldest items drop gracefully.
* **Batch Aggregation**: Messages flush in batches up to 250 lines or every 50ms.
* **Circuit Breaker**: When connection failures exceed threshold (e.g. 5 failures), state transitions to `Open`, preventing network spam for a backoff window (10s).
* **Exponential Backoff with Jitter**: Reconnection delay is calculated as $\min(t_{max}, t_{initial} \times 2^n) \pm \text{jitter}$.
* **Monotonic Sequences**: Sequences start at 1 and increment monotonically per message, allowing server-side deduplication and resume replay.
